🚦 Smart Traffic Light – AI Agents

Environment: Four-Way Smart Intersection

The intersection has four approach lanes (North, South, East, West). Each lane provides a percept containing:

  • Vehicle count – number of vehicles queued
  • Pedestrian button – whether a pedestrian has pressed the crossing button
  • Emergency vehicle – whether an ambulance / fire engine is detected

The traffic-light controller (the agent) must decide every time-step which direction to give a GREEN signal, while keeping all others RED.

Four Agent Types Compared

Agent Memory? Planning? Trade-off Reasoning? Key Strength
① Simple Reflex No No No Simplest – fast, transparent rules
② Model-Based Yes No No Remembers phase history → prevents starvation
③ Goal-Based Yes Yes No Guarantees no direction exceeds wait threshold
④ Utility-Based Yes Yes Yes Maximises a weighted score → best overall performance

① Simple Reflex Agent

Uses only IF–THEN condition-action rules. It looks at the current percept only – there is no memory. Each decision is independent of every prior step.

  • Rule 1 – Emergency detected → emergency_override
  • Rule 2 – Pedestrian button pressed → pedestrian_signal
  • Rule 3 – Vehicles waiting → set_green(direction)
  • Rule 4 – Empty lane → set_red(direction)

② Model-Based Reflex Agent

Maintains an internal state (model of the world) across time-steps: current green direction, phase timer, and accumulated wait counts. It combines the current percept with this stored model to decide.

  • Remembers which direction is currently green and for how long
  • Enforces a minimum green phase (10 steps) to avoid rapid flickering
  • Forces a phase change after a maximum (30 steps) to prevent monopolisation
  • Switches to the most congested waiting direction when the phase ends

③ Goal-Based Agent

Acts to achieve a defined goal: "No direction should wait more than 20 steps without receiving a green phase." It builds a plan (ordered list of green phases) that satisfies this goal and executes one step of the plan per cycle.

  • Directions approaching the threshold are promoted to the front of the plan
  • Goal is checked every step and violations are flagged
  • Plan is rebuilt whenever it becomes empty or a direction is at risk

④ Utility-Based Agent

Assigns a numerical utility score to every possible action and selects the one with the highest utility. This allows it to balance competing objectives automatically.

  • Throughput (×3) – vehicles that can be cleared
  • Fairness (×2) – how long the direction has been waiting
  • Emergency bonus (+100) – urgent override
  • Pedestrian bonus (+50) – safety
  • Phase-change cost (−5) – penalise premature switching

Prolog Source Files

The canonical implementations are in the agents/ directory of this repository. Key excerpts are shown below for the presentation.

agents/simple_reflex_agent.pl

% RULE 1 – Emergency override (highest priority)
decide_action(percept(Dir, _Count, _Ped, true), emergency_override(Dir)).

% RULE 2 – Pedestrian crossing
decide_action(percept(_Dir, _Count, true, false), pedestrian_signal).

% RULE 3 – Give green to a busy lane
decide_action(percept(Dir, Count, false, false), set_green(Dir)) :-
    Count > 0.

% RULE 4 – Empty lane → set red
decide_action(percept(Dir, 0, false, false), set_red(Dir)).

agents/model_based_agent.pl – key clause

% Dynamic state
:- dynamic current_green/1.
:- dynamic phase_timer/1.
:- dynamic wait_count/2.

% Switch to most congested direction when min phase elapsed
decide_action(percept(_, _, false, false), set_green(Best)) :-
    current_green(CG),
    phase_timer(T), min_green_steps(Min), T >= Min,
    most_congested_excluding(CG, Best),
    retractall(current_green(_)), assert(current_green(Best)),
    retractall(phase_timer(_)),   assert(phase_timer(0)).

agents/goal_based_agent.pl – goal check & planning

% GOAL: no direction waits more than max_wait steps
goal_satisfied :-
    max_wait(Max),
    \+ (waiting_time(D, W), W > Max).

% Build plan: urgent directions come first
build_plan :-
    max_wait(Max),
    Threshold is Max // 2,
    findall(W-D, (waiting_time(D, W), W > Threshold), Urgent),
    sort(0, @>=, Urgent, Sorted),
    pairs_values(Sorted, UrgentDirs),
    findall(D, (member(D, [north,south,east,west]),
                 \+ member(D, UrgentDirs)), OtherDirs),
    append(UrgentDirs, OtherDirs, NewPlan),
    retractall(plan(_)), assert(plan(NewPlan)).

agents/utility_based_agent.pl – utility function

% Utility weights
weight_throughput(3).  weight_fairness(2).
weight_emergency(100). weight_pedestrian(50).
weight_phase_change(-5).

compute_utility(Percepts, set_green(Dir), Utility) :-
    weight_throughput(Wt), weight_fairness(Wf),
    weight_emergency(We),  weight_phase_change(Wpc),
    member(percept(Dir, Count, _, _), Percepts),
    Throughput is Wt * Count,
    wait_time(Dir, WT),
    Fairness is Wf * WT,
    (member(percept(Dir,_,_,true), Percepts) -> Emg = We ; Emg = 0),
    (current_green(Dir) -> PC = 0 ;
        (phase_timer(T), min_green_steps(Min), T < Min -> PC = Wpc ; PC = 0)),
    Utility is Throughput + Fairness + Emg + PC.

% Select the action with the maximum utility
best_action(Percepts, BestAction) :-
    candidate_actions(Percepts, Candidates),
    maplist(scored_action(Percepts), Candidates, Scored),
    sort(0, @>=, Scored, [_Score-BestAction | _]).
